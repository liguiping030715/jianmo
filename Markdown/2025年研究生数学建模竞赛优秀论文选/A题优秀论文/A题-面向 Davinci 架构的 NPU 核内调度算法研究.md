## 摘 要：
面向通用神经网络处理器（NPU）的核内调度能够显著提升推理效率和能效。传统的人工编排方案任务复杂，难以充分考虑算子拓扑、片上存储和执行单元之间的耦合，容易导致缓存驻留过高和频繁的内存换入换出，从而增加DDR 流量并降低计算效率。为解决这些问题，本文提出一种基于华为Davinci 架构平台的核内通用调度算法，在不同问题情境下建立了峰值驻留、额外搬运量和总执行时间等目标优化模型。算法综合考虑碎片化、预取距离、模型泛化度等因素，并在Matmul、FlashAttention 和Conv 等算子数据上进行实验，综合优化驻留缓存容量、总额外数据搬运量、总执行时间指标。针对问题一，需求解一种驻留最大缓存容量尽可能小的优良调度序列，我们建立缓存峰值驻留调度求解模型。首先，对附件所给出的六个示例计算图进行数据分析，通过 Gephi 对附件计算图进行可视化，同时对数据进行模块化分析，为后续所建立模型的通用性和泛化性提供参考。其次，将问题转化为最小化缓存容量峰值的单目标模型，分别采用贪心算法、模拟退火算法、禁忌搜索算法、遗传算法进行求解，发现启发式算法求解本问题需要大量迭代与参数调节。最后选取贪心算法得出的最小缓存驻留容量作为本题求解结果，示例Conv0、Conv1、FlashAttention0、FlashAttention1、Matmul0、Matmul1 的结果分别为14664、14048、5140、8228、9728、35328。针对问题二，需再考虑总额外数据搬运量指标，为调度顺序中各缓冲区分配物理地址偏移，我们建立总额外数据搬运量优化模型。问题二分为以下两个子问题：基于调度序列的单目标优化问题和双指标融合的单目标优化问题。子问题一要求在问题一求得的调度序列𝑆基础上，额外考虑数据缓存区的地址偏移与SPILL 操作列表，设计一个总额外数据搬运量指标尽可能小的缓存分配方案。我们建立基于调度序列的单目标优化模型，使用遗传编程算法进行求解。子问题二考虑问题一在调度序列与指标最小化目标难以兼顾情况下，所需设计的优化调整方案。本文从模型泛化度的角度考虑，建立双指标融合的加权单目标模型，采用变邻域模拟退火算法进行求解。最后，通过两个子问题结果的对比发现，基于调度序列的单目标优化模型所取得的结果更优，示例Conv0、Conv1、 FlashAttention0、FlashAttention1、Matmul0、Matmul1 的总额外数据搬运量分别为230496、 840904、4096、33792、41600、518400。针对问题三，需额外考虑算子总运行时间指标，来实现其与总额外数据搬运量指标的优化，我们建立综合性能优化策略设计模型。问题三需求解以下两个阶段的问题：算子运行时间约束下的加权指标优化问题和多目标性能优化问题。其中，阶段一考虑仅优化总运行时间指标，我们设定总额外数据搬运量最多增加10%，寻找在调度顺序不变的情况下，能够优化缓存分配的方案。我们使用GP 改进算法求解得到使两项指标加权值

# 一、 前言

## 1.1  问题背景

## 为面向通用NPU 的核内调度研究，首先需要厘清关键技术与发展脉络。以SIMD

## 为抽象，本题以华为Davinci 架构平台来进行开展讨论，计算核心由多类执行单元与多

## 级片上存储共同构成：计算单元包括专用于矩阵乘的Cube 与通用向量计算的Vector，

## 数据搬运单元包括MTE1/2/3 与FIXP；各单元拥有独立队列，由统一调度核心分发指令

## 协同工作。片上存储呈分层结构：紧邻Cube 的L0A/L0B/L0C（分别承载左右操作数与

## 结果）、容量更大的L1，以及面向Vector 的统一缓存UB；MTE 支持在L1 与UB 间交

## 换以适配不同算子交替执行。为适配硬件，推理算子被进一步拆解为在特定单元上执行

## 的原子操作，连同ALLOC/FREE 等缓存管理指令，构成带依赖约束的细粒度计算图

## （DAG），调度任务的首要目标是在满足依赖的前提下给出有效拓扑序列，驱动多单元

## 协同执行。

## 围绕这一硬件——软件抽象，算子级优化逐步演进：以Matmul 为例，典型分块计

## 算由COPY_IN（DDR→L1）、MOVE（L1→L0A/L0B）、MMAD（Cube 计算）、COPY_OUT

## （写回DDR）四阶段构成；通过在分块间交错这些阶段可形成流水并行，但不同分块访

## 问顺序会显著影响重复载入与DDR 流量，例如“之字形”顺序即可降低对某一矩阵块的

## 重复换入次数。进一步地，FlashAttention 通过分块与在线softmax 将中间结果留在高速

## 缓存中，成为注意力加速的关键；其子结构同时依赖Cube 与Vector，需要在二者之间

## 构建分阶段交替的流水以提高利用率。卷积网络的多层依赖则带来深/广两类调度策略

## 选择，不同策略会改变各层间的驻留重叠与复用。

## 然而，随着图规模与异构度上升，现有流程暴露出瓶颈：其一，片上存储容量与连

## 续地址约束使缓冲区生命周期大量重叠，易触发空间紧张与碎片化，需要在调度中显式

## 为每个缓冲区分配连续区间并处理地址复用依赖；当陷入“资源死锁”时必须引入SPILL

## （换出/换入）以暂存DDR，从而换取可行性。其二，SPILL 会带来额外数据搬运量与

## 时延，且代价与是否被COPY_IN 使用有关，如何选择目标缓冲区与时机直接影响系统

## 能效与性能。其三，调度目标相互牵制：一方面需寻找内存友好的拓扑序以降低峰值驻

## 留并尽量避免SPILL，另一方面又要在资源独占与依赖约束下实现多单元并行以缩短总

## 执行时间，二者往往难以同时最优。

## 据此提出一套通用的面向华为Davinci 架构平台的核内调度算法。首先，进行内存

## 感知的拓扑排序：在就绪集合中优先调度可立即释放大体量缓冲区的FREE，其次选择

## 能解锁后续FREE 的计算节点，最后才进行ALLOC（小块优先）；结合关键路径权重，

## 获得兼顾驻留与并行潜力的顺序，以降低峰值驻留并为后续容量约束创造空间。随后，

## 基于该顺序构建多级缓存地址分配与SPILL 策略：将L1/UB/L0*视为可合并空洞的连

## 续区间，采用最佳/首次适配分配地址；当需要连续空间而短缺时，以“下次使用最远+代

## 价权重”的Belady 类抉择选择SPILL 目标，并在下一次使用前进行Just-in-Time 的

## SPILL_IN，必要时重映射以抑制碎片。最后，在插入SPILL 与地址复用依赖后，执行异

## 构列表调度与软流水：按资源独占与执行依赖约束，结合关键路径优先和预取距离控制，

## 使Cube/Vector/MTE/FIXP 阶段交错以最大化重叠；若需要，可在不改变SPILL 次数的

## 窗口内做小规模顺序交换以进一步压缩完工时间。上述流程与赛题提供的Matmul、

## FlashAttention 与Conv 示例相匹配，可在不针对特定结构“过拟合”的前提下验证算法在

## 不同算子形态上的普适性。

# 1.2  问题研究现状

# 在深度学习的快速发展中，神经网络处理器（NPU）作为关键的硬件加速器，其性

# 能和能效受到越来越多的关注。特别是在边缘计算领域，基于单指令多数据流（SIMD）

# 架构的NPU 因其设计简洁和高计算效率，成为主流选择。然而，如何有效地利用这一

# 类硬件加速器，其软件模型的适配性已经成为一个关键瓶颈。随着复杂神经网络的出现，

# NPU 的硬件资源配置和调度问题愈发突出，亟待解决。

# 调度优化研究的演进可以追溯到早期宏观层面的任务分配问题。在传统的调度领域，

# 很多研究集中于如何进行资源分配，尤其是在复杂约束下生成无冲突的排班表。例如，

# 国际空间站的宇航员排班和放射肿瘤科的员工调度，都采用了基于约束的算法，确保任

# 务的有效分配[1] [2] 。然而，随着计算技术的进步，调度研究的重心逐渐从宏观层面的任

# 务调度转向了微观层面的硬件资源调度。对于CPU 而言，单一的SIMD 指令虽然可以

# 提高并行度，但端口争用和资源竞争可能导致性能下降[3] ，这表明硬件资源的限制直接

# 影响着调度的效率。

# 随着大型语言模型等复杂AI 任务的出现，单一的硬件加速器已无法满足端到端的

# 推理需求，异构硬件协同调度因此成为研究的热点。例如，IANUS 系统将NPU 与存内

# 计算（PIM）结合，以同时发挥两者的优势[4] 。其中的核心挑战在于如何在多个计算单

# 元之间协调任务，同时最小化数据在内存中的移动，这要求在统一的内存系统和PIM 访

# 问调度之间找到一种高效的协同机制。这类研究强调，现代硬件中高效的计算调度必须

# 与数据流优化相结合，因为数据搬运的开销已成为性能的主要瓶颈。

# 与此类似，一些研究专注于通过数据流调度技术来降低内存访问开销，特别是在卷

# 积神经网络中，采用层分组（layer grouping）和分块（tiling）策略来最大化片上缓存的

# 复用，从而有效减少片外内存的访问开销[5] 。此外，内存计算（IMC）的逻辑编译器也

# 需要同时考虑逻辑综合和调度，以生成高效的指令序列，优化能效和时延[6] 。这些研究

# 为现代硬件的高效调度提供了宝贵的经验和方法。

# 与上述挑战类似，针对基于SIMD 架构的通用NPU 核心，本文提出的调度问题正

# 是这些挑战的缩影。综上所述，本文通过解决计算与内存协同的独特挑战，将宏观调度

# 中的自动化思想应用于微观的硬件层面，旨在为通用NPU 的调度瓶颈提供一种高效且

# 可扩展的解决方案。这不仅能推动深度学习加速器的应用，还能为未来硬件设计与调度

# 优化提供理论和实践指导。

# 1.3  问题重述

# 基于提供的背景和任务，本题的核心是为通用神经网络处理器（NPU）设计一套高

# 效的核内调度算法。该算法旨在将神经网络计算图中的原子操作，在满足严格依赖关系

# 的前提下，优化地调度到NPU 的异构硬件单元上，并妥善管理有限的多级缓存资源。

# 具体任务可分解为以下三个相互关联且层层递进的子问题：

# 问题一：最小缓存驻留调度问题

# 基于给定的计算图，问题一的核心任务是设计一个调度算法，通过合理的拓扑排序，

# 使得执行过程中所需的最大缓存容量尽可能小。在没有硬件容量限制的前提下，我们需

# 要尽量减少内存峰值，以防止缓存溢出。这与数据流的优化方向相符：通过合适的计算

# 图调度顺序，优化缓存的使用，从而降低内存占用峰值。为此，调度算法需要依赖缓存

# 的生命周期与节点间的依赖关系，以实现内存的高效复用和合理分配，从而保证调度过

# 程中的内存压力最小。

# 问题二：缓存分配方案单目标设计问题

<!-- Page 7 -->

# 问题二的目标是为计算图中的每个缓冲区分配具体的内存地址，并在有限的硬件缓

# 存容量下，通过合适的SPILL 策略优化数据搬运量。在硬件缓存容量有限的情况下，如

# 何合理分配内存地址、避免缓冲区重叠并减少换入换出的数据量，是影响性能的关键。

# 缓存分配策略不仅要考虑内存的物理容量限制，还要考虑缓存的连续地址分配，以避免

# 碎片化导致的额外开销。同时，SPILL 机制的引入使得调度算法在内存不足时能够及时

# 释放缓存空间，并在需要时将数据重新加载，从而确保计算过程不受内存限制的影响。

# 问题三：综合性能优化策略设计问题

# 3.3.1 贪心算法的适应性分析

# 贪心算法（Greedy Algorithm）是一种在每一步选择中都采取在当前状态下最优的选

# 择，希望通过每一步的局部最优，最终得到全局最优解的方法。通俗地讲，贪心算法总

# 是只看眼前利益，每一步都“贪”当前最好的，不回溯、不修改[28] 。

# 在本问最小缓存驻留调度问题中，贪心算法的应用与活动选择问题有相似之处。我

# 们首先根据每个任务的内存需求和执行周期对任务进行排序，优先选择内存需求较小或

# 执行周期较短的任务，这样可以有效减少整体缓存的峰值驻留，避免在调度过程中出现

# 内存瓶颈。然后，每次选择一个任务时，判断其开始时间是否与前一个已选择任务的结

# 束时间相符，如果符合条件，则选择该任务并更新当前的缓存驻留值，重复此过程直到

# 没有更多任务可以选择[28] 。

# 通过这种贪心策略，我们确保了每一步选择的局部最优解，即每次选择一个任务时，

# 都是当前条件下缓存需求最小的任务，从而最小化最大缓存驻留量。这种方法能够在有

# 限的硬件资源下，快速找到合适的调度顺序，从而降低内存峰值，提升计算效率。

# （1）模拟退火算法（Simulated Annealing）

# 模拟退火算法是一种模拟物理退火过程的全局优化算法。在算法中，通过模拟物质

# 在热力学平衡条件下的退火过程，使得系统逐渐达到一个最低能量状态，从而获得问题

# 的最优解。具体而言，模拟退火算法通过引入温度参数控制搜索过程中的随机性，在每

# 一步选择一个新解时，如果该新解比当前解更优，则直接接受；如果新解较差，则以一

# 定的概率接受，从而避免陷入局部最优解。随着温度的逐渐降低，算法的随机性逐渐减

# 弱，最终收敛于全局最优解。该算法适用于大规模、复杂的优化问题，但在某些情况下，

# 退火过程的温度控制和退火速度的选择可能对结果有较大影响[7] [24] 。

# （2）遗传算法（Genetic Algorithm）

# 遗传算法是一种基于自然选择和遗传学原理的优化算法。它模仿了生物界中的自然

# 选择和遗传机制，通过选择、交叉和变异等操作模拟种群在进化过程中逐代改善适应度

# 的过程。遗传算法的核心思想是通过对一个初始种群的个体（候选解）进行繁殖，形成

# 新的种群，并不断选择适应度较高的个体进行交叉和变异，从而生成更加优良的解。在

# 每一代中，适应度更高的个体有更大的机会传递其基因（解决方案的部分信息）到下一

# 代，最终找到全局最优解。遗传算法的优势在于能够有效地搜索大范围解空间，且对局

# 部最优解有较强的跳出能力。然而，它的缺点是收敛速度可能较慢，且在复杂问题中，

# 如何设置合适的交叉率、变异率和选择策略仍是关键问题。

# 禁忌搜索算法是一种基于局部搜索的优化算法，它通过引入“禁忌表”机制避免在搜

# 3.6  算法时间复杂度分析

# 本题要求“分析算法相对于节点总数𝑁的时间复杂度”，这一点对于启发式算法来说

# 并不适用。启发式算法通常无法提供明确的时间复杂度，它们的时间复杂度往往依赖于

# 多个因素（如温度下降的速度、种群大小、迭代次数等），而且不保证能在每次运行时得

# 到最优解。因此，启发式方法的时间复杂度无法准确衡量，也就失去了分析和比较的基

# 础。为了保证可以进行合理的分析和比较，在本文中，我们将不对启发式算法进行理论

# 分析。

# 在分析最小缓存驻留调度问题的时间复杂度时，选择最优解的步骤尽管有时间复杂

# 度，但它只是对已生成的调度序列进行简单的比较，不会显著增加总复杂度，因此可以

# 忽略。其次，问题的核心计算过程集中在生成调度顺序和计算缓存驻留量，这两个步骤

# 的计算量直接影响算法的时间复杂度。而选择最优解的步骤只是额外的遍历，不会对整

<!-- Page 28 -->

# 体复杂度产生实质性影响。此外，对于像动态规划和贪心算法等算法，最优解是逐步构

# 建的，不存在单独的“选择最优解”步骤，因此这些算法的时间复杂度通常没有单独的选

# 择步骤，最优解的选择是在计算过程中实时更新的，不需要单独考虑。

# 同时，虽然不同算法生成的可行解数量不同，暴力求解可能枚举所有合法调度序列，

# 而动态规划或贪心算法可能通过优化策略找到更少的可行解，但由于计算最大缓存驻留

# 量的时间复杂度为 O(N)，我们将复杂度集中在计算每个可行解的最大缓存驻留量上，

# 而不考虑可行解数量的差异。这样，尽管不同算法生成的解空间大小不同，每个解的缓

# 存驻留量计算时间通常是 O(N)，因此这部分复杂度可以统一比较。

# 最后，完整的拓扑排序检查通常需要遍历所有的边（即E 条依赖边），所以时间复

# 杂度应为 O(N+E)，这与节点数和边数都有关，同时还要与对应的算法可行解数量相乘。

# 由于本问聚焦于“算法相对于节点总数N 的时间复杂度“，且在计算最大缓存驻留量时我

# 们排除了可行解数量差异，因此我们在本题不考虑拓扑排序有效性检验的时间复杂度。

# 4.2.2 变邻域模拟退火算法的适用性分析

# 传统的模拟退火算法（SA）通过逐步降低温度来避免陷入局部最优解，但有时其扰

# 动方式较为单一，可能导致收敛速度较慢，或者无法充分探索解空间。而变邻域模拟退

# 火算法（VN_SA）通过引入变邻域搜索（VNS）的思想，在搜索过程中不断改变邻域结

# 构，即每次搜索的扰动方式发生变化。这种机制使得VN_SA 能够在更广泛的解空间内

# 进行搜索，避免了局部最优解的困境，提高了找到全局最优解的概率。因此，当以问题

# 1 中的调度序列为基础进行缓存分配时，VN_SA 能够更有效地调整调度序列，寻找最佳

# 的缓存分配方案，最小化总额外数据搬运量。

# 在本问中，缓存分配方案的优化不仅依赖于调度序列，还涉及如何在满足硬件限制

# 的情况下，合理安排缓冲区的数据驻留顺序。使用问题1 中的调度序列作为初始解可能

# 无法最小化总额外数据搬运量，尤其是在缓存容量受限的情况下。VN_SA 可以通过变

# 邻域操作，在调整调度序列时对缓存分配进行优化。具体而言，VN_SA 能够灵活地选

# 择不同的邻域结构（如改变缓存分配的顺序、调整数据搬运的时机等），从而探索更多的

# 调度序列和缓存分配组合，寻找可能更优的调度方案。

# （a）首次适应（First-Fit）改进

# 六、 主要结论与模型评价

## 6.1  模型的优点

## （1）针对问题一，本文以“贪心算法初解+多启发式优化”构建调度框架，能够覆盖多

## 种算子组合与内存模式，又有利于在不同数据集和任务场景间直接迁移，充分体现了方

## 法的通用性与泛化性。

## （2）贪心算法基于就绪集和优先队列的实现，能够将时间复杂度控制在较低的范围，

## 使得算法运行更高效，适合大规模数据处理。并且其的解易于复现和验证，为后续优化

## 算法的比较提供了清晰的基准。

## （3）问题二子问题一通过遗传编程（GP）算法进行单目标优化模型，能够为缓存分

## 配方案提供高质量解，且易于理解和实现。

## （4）问题三建立的“递进优化+多目标帕累托搜索”的综合框架，显著提升了模型的

## 实际性能导向与决策支持能力。

## 6.2  模型的不足

## （1）启发式方法不保证全局最优，在依赖极密或峰值由全局耦合触发的实例上，改

## 进幅度可能有限。且各启发式算法中退火温度、邻域次数、交叉/变异概率、NSGA-II 种

## 群规模等参数的设定对结果存在影响。

## （2）贪心算法的主要缺点是容易陷入局部最优解，未必能找到全局最优解，尤其在

## 复杂的计算图中，可能无法处理所有的约束条件。

## （3）遗传编程算法的计算复杂度较高，特别是在大规模计算图和多种约束条件下，

## 可能需要较长的时间来收敛到最优解。

## （4）问题二子问题二的加权单目标模型存在权重设定的主观性，可能影响解的帕累

## 托最优性。

## （5）问题三建立的“递进优化+多目标帕累托搜索”的综合框架计算复杂度极高，特

## 别是帕累托搜索对计算资源需求巨大，在效率上存在优化空间。
