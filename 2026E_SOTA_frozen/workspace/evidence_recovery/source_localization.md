# 2026E source-localization contract — Stage 2.5

Every evidence locator carries **version, split, source key, modality, start/end indices, resolution, and uncertainty**. Local Attachment 3 file keys are not invented CMU IDs. Attachment 4 local `01`–`20` keys link feature PKLs and the corresponding versioned MP4s; Attachment 1 keeps its official video/clip ID. Raw media and frozen v2 data remain unchanged.

| Modality | Strongest current locator for Attachment 2/3/4 features | When raw media is available | Forbidden overclaim |
|---|---|---|---|
| Text | Token index or contiguous token interval. For A2 and A4 `raw_text`, the pinned tokenizer's character offsets support a phrase span in the original transcript. Unaligned A3 has raw-text phrase spans; aligned A3 has only supplied token IDs and 131 active ID-100 positions without recoverable wording. | Phrase can be displayed with sample key and character/token offsets. No word-level spoken timestamp is supplied. | No exact speech seconds from token index or uniform word spacing. No reconstruction of aligned A3 ID-100 wording from the paired unaligned version. |
| Audio | Half-open interval `[i,j)` of aligned 50 or unaligned 500 feature rows, with `P/O` state and version. | Attachment 1/4 MP4 audio packet PTS and clip-relative seconds are verified at the media level by [timebase audit](media_timebase.md). A newly extracted waveform feature can get verified time only if extraction logs its sample/packet interval and time base. | Existing PKL feature indices are **not** verified audio seconds; no exact audio-feature-to-packet map is supplied. |
| Vision | Half-open interval `[i,j)` of aligned 50 or unaligned 500 feature rows, with `P/O` state and version. | Attachment 1/4 displayed MP4 frames have verified clip-relative PTS. A newly extracted visual feature can be tied to frame index/PTS only with an explicit extraction map. | Existing PKL feature indices are **not** verified frames or seconds. `vision_lengths` cannot certify the unaligned endpoint. |

For Q3 Attachment 4, a source locator is therefore a tuple such as `local_key=01, version=aligned_50, modality=vision, feature_rows=[12,16), media_file=.../01.mp4, time_seconds=null, resolution=feature_interval, mapping_uncertainty=feature_to_frame_unknown`. A text locator may instead carry `token_rows`, `character_span`, and the exact phrase; its `spoken_time_seconds` remains null. If the evidence is an actual decoded video frame from Q1, include its verified frame PTS and declare `resolution=decoded_frame`, but do not claim that a PKL feature row selected that frame without a logged map.

This contract records the strongest **currently defensible** evidence resolution: phrase/token for text and feature interval for audio/vision, plus verified media frame/audio packet times **where directly measured**. Exact source media localization for an existing audio/vision PKL feature remains unresolved; a later paper must not claim more than the saved map supports. Reports must distinguish evidence that localized a model feature from illustrative media nearby. Timing uncertainty is an explicit field, not a hidden footnote.
