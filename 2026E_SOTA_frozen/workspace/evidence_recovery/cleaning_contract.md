# 2026E Stage 2.5 — minimal preprocessing contract

Status: **rules frozen before execution**. Execution records and sanity checks are written to `workspace/data_audit/cleaning_report.md` and `workspace/results/data_audit/cleaning_statistics.json`. `workspace/data/raw/` remains immutable; derived arrays and manifests belong under `workspace/data/processed/`. This contract uses the official statement and the direct Stage 2 audit. It does not infer that every zero vector is missing.

## Three separate states

For modality `m`, sample `i`, and native position `t`:

- `P_imt ∈ {1,0,?}`: position is within the defensible source sequence (`1`), known padding/outside it (`0`), or unresolved (`?`). Text attention mask and unaligned audio lengths support `P` directly. Unaligned `vision_lengths` is **not** a trustworthy prefix endpoint; aligned audio/vision lack length fields. Attachment 3 has no length fields.
- `O_imt ∈ {1,0,?}`: usable original observation, known injected/unavailable observation, or unknown. `O=1` requires `P=1`; `P=0` implies `O=0` for computation but means padding, not a missing event. A valid all-zero vision vector may have `O=?`, and an Attachment 3 zero run is a **candidate** missing interval without an official mask. Never apply `x_imt=0 ⇒ O_imt=0`.
- `R_imt`: model-estimated reliability conditional on a usable input. No quality/reliability field is provided. `R` is **not a preprocessing label**, and must not be manufactured from zero magnitude. Future learned `R` parameters may use only Attachment 2 train, with structure/hyperparameters chosen on valid.

Keep `P`, `O`, and `R` separate in every processing record. Store unknown states explicitly rather than silently coercing them to 0 or 1. Do not compute train statistics from known padding, synthetic gaps, or unresolved observations. If a numerical tensor needs a placeholder, use a declared value *after* storing the masks; the placeholder itself carries no missingness meaning.

Every executed transformation must append a per-run manifest with input hash, output path, code/config version, row count and mask counts.

## Interface and timebase gates before a pilot

1. **Text:** the aligned Attachment 3 cast is verified exact for 30/30 files. This resolves dtype conversion, not the choice of tokenizer/encoder. Unaligned Attachment 3 has `raw_text` only. A model trained on precomputed Attachment 2 `text` cannot receive the same field from Attachment 3.
2. **Masks:** text `P` and unaligned Attachment 2 audio `P` are supported. Unaligned vision and Attachment 3 terminal gaps remain unresolved. A restricted pilot may use only trusted positions with unknowns explicit; it may not claim exact official gap labels.
3. **Time:** MP4 container `mvhd` durations were read from all 140 videos. Attachment 1 spans exactly 2.648–34.567 s, matching the statement. OpenCV's decodable frame counts still disagree with metadata in 122/140 files, so frame-to-second and feature-to-source mapping need an independent timestamp-aware decoder/verification. No word timestamps were supplied. See [timebase evidence](timebase_evidence.md).

**Execution boundary:** preserve every original all-zero row in numerical features; assign `P/O=?` where metadata cannot distinguish native zero, padding and special missingness. No processing step may promote a suspected gap to an official missing-mask label. The Stage 2 `BLOCKED` state remains until the full input contract is recovered. This contract does not authorize Stage 3 modeling.
