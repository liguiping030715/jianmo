Use the same tokenizer settings for raw text: `padding='max_length', truncation=True, max_length=50`, with the locally pinned uncased vocabulary. The token audit compares every supplied token triplet with this rule: A2 aligned and unaligned train/valid/test **3,395/728/727 exact each**, and A4 aligned/unaligned **20/20 exact each**. Evidence: [tokenizer compatibility JSON](tokenizer_compatibility.json). The pretrained encoder is applied identically after either stored or generated tokens; its outputs must be computed with a declared train-only fine-tuning policy if later used, never fitted on A3/A4.

A2 precomputed continuous `text` must **not** be used as the required text input: A3 has no corresponding `text` feature in either version. The pinned pathway creates comparable BERT states from fields present in every required split of each version. Tokenization is an in-memory model interface; it does not alter frozen v2 or constitute new cleaning.

**A3 aligned caveat.** The aligned A3 triplets retain their original attention/type rows but 27/30 samples differ from tokenization of the paired unaligned `raw_text` at 131 active token IDs, all equal to ID 100 (`[UNK]`). This is consistent with a text-local intervention but does not prove the official generator or missing label. Keep the supplied aligned A3 IDs; mark `O=2` at active ID-100 positions and `P=1` from its supplied attention. Do not backfill them from the paired unaligned text. Aligned A3 has no raw transcript or original ID, so those positions cannot support phrase wording. Unaligned A3 does supply raw text; it is an independent same-version interface and must not be used to overwrite aligned A3.

This resolves a common executable text encoding pipeline, **not** word-level media timestamps, unknown-token meaning, or feature-to-raw-media alignment. Those limits belong to the observation and source-localization contracts.
