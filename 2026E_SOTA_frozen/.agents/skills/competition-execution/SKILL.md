# Competition Execution

## Principles

- Secure a complete baseline solution early.
- Front-load interpretation, Stage 1.1 targeted literature scan, and data/schema risk.
- Literature scan is time-boxed; it must narrow candidates, not become a survey-paper project.
- Run falsifiable pilots before expensive optimization.
- Maintain blockers and fallback models.
- Freeze core choices early enough to leave substantial validation/writing time.
- Prefer validated simple methods over unstable sophisticated ones.

## Suggested relative phases

Adapt to contest duration/team size:

- first 5–8%: problem selection and decomposition,
- next 5–8%: targeted SOTA literature scan + historical retrieval + negative-transfer audit,
- next 8–12%: data audit + solution architecture finalization,
- next 20–25%: baselines and pilot comparison,
- middle 25–30%: full model chain and evidence generation,
- next 12–18%: robustness/sensitivity/explainability/error analysis/visualization,
- final 15–20%: paper integration, consistency audit, formatting, submission checks.

If Stage 1.1 is still expanding after it has already identified one baseline and two serious mechanism candidates per major stage, stop searching and move to data/pilots.
